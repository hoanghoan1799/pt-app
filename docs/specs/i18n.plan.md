# Plan: i18n

## Source

- Intent: none
- Spec: `docs/specs/i18n.md`
- KAN key: none (no ticket for this work)

## Files that change

- `package.json`, `pnpm-lock.yaml`: add `next-intl`.
- `db/schema.ts`: nullable `locale` on `users` and `admins` (additive).
- `utils/locale.ts`: locale constants and parsers (mirrors `utils/theme.ts`).
- `i18n/request.ts`, `i18n/messages.ts`, `i18n/types.ts`, `i18n/translator.ts`: request config, merged messages, typed keys, non-request translator.
- `messages/{vi,en}/{common,layout}.json`: shell strings.
- `next.config.ts`: `createNextIntlPlugin`.
- `services/locale-actions.ts`, `services/locale-cookie.ts`, `services/admins.ts`, `services/users.ts`, `features/auth/services/auth-actions.ts`: set the locale, persist on the account, re-apply at login.
- `app/layout.tsx`, `app/offline/page.tsx`, `app/global-error.tsx`: lang attribute, provider, localized metadata and copy.
- `components/layout/**`, `components/common/**`, `components/VerifiedBadge`: strings moved to messages; language group in `HeaderMenus`.
- `i18n/__tests__/*`, `utils/__tests__/locale.test.ts`: guard and unit tests.
- `README.md`, `CLAUDE.md`: feature line and convention.

## Order of work

1. Schema column and `utils/locale.ts`.
2. next-intl wiring, messages loader, types, translator.
3. Locale action and login hook.
4. Shell components and switcher.
5. Tests, `pnpm verify`, dev server check of `<html lang>`.

## Risks

- Every route already reads cookies, so no new dynamic cost.
- `global-error` is always Vietnamese (documented).
- Date formats in `utils/week.ts` stay Vietnamese until PR 5; mixed language on the English shell is expected until then.
- Schema change is additive and nullable, safe for `drizzle-kit push`.

## Proof

- `i18n/__tests__/messages.test.ts`, `i18n/__tests__/translator.test.ts`, `utils/__tests__/locale.test.ts`.
- `pnpm verify`; `curl` with and without `Cookie: locale=en` shows `<html lang>`.
