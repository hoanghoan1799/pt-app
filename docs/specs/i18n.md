# i18n: Vietnamese (default) + English + Chinese

No Jira key (none for this work). Plan: `docs/specs/i18n.plan.md`.

## Decisions

- Library: `next-intl` 4.x, "without i18n routing": no URL prefix, no locale middleware.
- Locale lives in the `locale` cookie (`utils/locale.ts`, same shape as `utils/theme.ts`): `LOCALES = ["vi", "en", "zh"]`, default `vi`, 1 year, httpOnly. `i18n/request.ts` reads it and falls back to `vi`; `timeZone` is fixed to `Asia/Ho_Chi_Minh`.
- `setLocaleAction` (`services/locale-actions.ts`) ignores invalid values, sets the cookie and, when a trainee or admin session exists, saves the choice in the nullable `users.locale` / `admins.locale` column (additive schema change). Session lookup uses `getCurrentUser` / `getAdminSession` from `services/auth-guard.ts`, which return null when signed out. Login (`loginUserAction`, `loginAdminAction`) re-applies the stored locale to the cookie so a new device follows the account.
- Switcher: "Ngôn ngữ / Language" group in the gear (Cài đặt) menu of `HeaderMenus`, under the theme options. Language names are shown in their own language and are not translated.
- Types: `i18n/types.ts` augments next-intl's `AppConfig` with `Locale` and `Messages` (from the vi files), so `t("key")` is type-checked.
- `app/global-error.tsx` has no root layout, no cookie access and no request config; it is always Vietnamese (provider with vi messages).
- Out of PR 1: `utils/week.ts` / `utils/month.ts` Vietnamese date formats, `features/**` strings.

## Layout of messages

```
messages/vi/<namespace>.json
messages/en/<namespace>.json
messages/zh/<namespace>.json
```

`i18n/messages.ts` imports every file statically and merges them into one object per locale, keyed by namespace (`{ common, layout }`). Nested keys use dot paths: `useTranslations("common.week")` then `t("today")`.

Namespaces so far: `common` (shared UI in `components/common`), `layout` (app shell, `components/layout`, offline page, metadata).

## Add a string

1. Add the key to `messages/vi/<ns>.json` and the same key to `messages/en/<ns>.json`.
2. Client or shared component: `const t = useTranslations("<ns>.<group>")`. Async server component or metadata: `await getTranslations(...)`. Outside a request (push, services, tests): `getTranslator(locale, ns)` from `i18n/translator.ts`.
3. Dynamic values use ICU placeholders: `"Photo of {name}"`, with the same placeholder names in both languages.
4. A new namespace: create both files and register them in `i18n/messages.ts`.
5. `pnpm test` runs `i18n/__tests__/messages.test.ts`: identical key sets (missing paths are reported), identical placeholders, no empty strings, every file registered.

## Server messages

Action results, Zod issues and API replies are built from Vietnamese constants (`*_MESSAGES`, schema strings) and tests assert them, so the constants stay canonical. `messages/<locale>/errors.json` holds the same strings (vi equals the constants; a test checks it) and `i18n/localize-message.ts` maps a known Vietnamese message (also templated ones such as `Tối đa {max} ký tự`) to the active locale; unknown text passes through. `withFormErrorHandling` / `withResultErrorHandling` apply it to `message` and `fieldErrors` on every action; API routes use `localizeResult`; browser-raised texts use `useLocalizeMessage`. Messages with locale-dependent values use `getErrorsTranslator()` (`toasts.*`). Add a new server message: constant + `errors.json` key in both locales.

## Chinese (zh)

- Simplified Chinese (`zh`, Intl tag `zh-CN`, flag 🇨🇳, shown as "中文"). Traditional can be added later as its own locale.
- Dates: `formatDayMonth`/`formatShortDate` give "11月2日", `formatMonthName` gives "11月", week titles "2026年11月2–8日", chat search results add "2025年" for other years. Covered by `utils/__tests__/format-zh.test.ts`.
- Push, server errors and formatters load `zh` through the same narrow translators (`i18n/format-translator.ts`, `i18n/push-translator.ts`, `i18n/localize-message.ts`).
